# Day 5: RAG, Knowledge Retrieval & Local Agent Evaluation

## 1. 学习目标

今天的重点是理解：

- RAG 为什么是 agent 重要的知识增强方式
- 知识检索和模型生成之间的关系
- 为什么本地 agent 也需要“知识入口”
- 如何评估一个 agent 是否真的在完成任务
- 什么是更实用的 agent 设计思路

## 2. RAG 的核心思想

RAG（Retrieval-Augmented Generation，检索增强生成）并不是简单地“让模型多说一点”，而是：

- 先检索相关资料
- 再把这些资料作为上下文给模型
- 最后让模型基于真实信息做回答

它的核心价值在于：

- 让模型更贴近当前任务的真实数据
- 减少凭空编造的内容
- 让回答更有依据
- 让 agent 能利用本地知识库、文档库和业务数据

## 3. 为什么 RAG 很重要

很多真实问题都不能只靠模型的训练记忆来回答，因为：

- 信息可能更新得很快
- 业务知识不是公开知识
- 私有文档和内部资料无法直接进入模型训练
- 某些需求需要结合特定上下文

因此，agent 需要：

- 能搜索知识
- 能过滤相关片段
- 能在有限上下文中引用关键信息
- 能在生成答案时保持事实依据

这就是 RAG 的重要意义。

## 4. RAG 与普通 Chatbot 的区别

### 普通 Chatbot

- 主要依赖模型参数和对话历史
- 可能知道一些常识
- 对新信息或私有信息不一定了解
- 在特定文档场景里容易“猜测”

### 带 RAG 的 agent

- 先查找相关知识源
- 读取目标文档或数据库内容
- 把信息作为上下文
- 再生成更准确的回答

这使得它更适合：

- 文档问答
- 知识库助手
- 企业内部问答
- 代码理解与检索
- 学习资料总结

## 5. 检索的意义

检索不是为了“把更多内容塞给模型”，而是为了：

- 找到最相关的信息
- 去掉无关噪音
- 提高答案质量
- 让模型看到“真正有用的背景”

一个好的检索系统通常要关注：

- 查询是否准确
- 文档是否足够相关
- 结果是否按重要性排序
- 是否保留了关键上下文片段

如果检索质量差，后续生成质量也会受影响。

## 6. RAG 在本地 agent 中的作用

在本地 agent 场景中，RAG 可以帮助我们：

- 读取项目里的 notes、README、代码说明
- 基于本地资料回答“这个项目是怎么组织的？”
- 搜索某个关键词并给出引用位置
- 结合多个文档生成更完整的总结

例如，我们当前这个项目里，就可以设计：

- 一个文档索引工具
- 一个关键词搜索工具
- 一个读取文件工具
- 一个总结工具

这些组合起来，就形成了一套很典型的 local RAG workflow：

用户问题 → 检索相关文档 → 读取关键内容 → 总结答案

## 7. Agent 的真实能力，不只是回答，而是完成任务

对一个 agent 来说，真正重要的不只是“输出一段文字”，而是：

- 能否理解任务
- 能否判断需要什么信息
- 能否拿到正确上下文
- 能否调用合适工具
- 能否基于证据给出答案
- 能否在失败时进行修正

这意味着，一个好的 agent 往往需要：

- 清晰的任务目标
- 可用的工具集合
- 结构化的输入输出
- 可管理的上下文
- 对结果的评估机制

## 8. 评估 agent 的关键维度

评估 agent，不应该只看它“说得像不像”，而要看它是否真的完成任务。

### 常见评估维度

- 准确性：答案是否正确
- 完整性：是否覆盖关键信息
- 相关性：是否提到了真正有用的内容
- 一致性：是否保持上下文和任务要求一致
- 工具使用是否合理：是否真的用上了必要工具
- 任务完成度：是否达成用户目标

一个 agent 可以“看起来很像一个助手”，但如果它没有拿到必要资料、没有调用工具、没有遵守要求，那么它仍然不算一个可靠 agent。

## 9. 一个本地 agent 的理想结构

一个实用的本地 agent，通常会包含这些部分：

- 用户输入
- 系统提示词
- 任务目标
- session / memory
- 可调用工具列表
- 文档搜索与读取工具
- 检索结果
- 最终回答生成

它的流程通常是：

输入 → 任务理解 → 选择工具 → 检索资料 → 读取结果 → 综合判断 → 输出回答

在这条链路中，每一步都决定了最终质量。没有任何一步是“无关紧要”的。

## 10. 为什么 context 和 retrieval 同样重要

很多人容易忽略一点：

- 模型有知识，但不代表它知道哪个信息最有用
- 工具能调用，但不代表它会选择正确工具
- 检索能找资料，但不代表它会正确用这些资料

所以 agent 的关键不在于“模型有多强”，而在于：

- 上下文是否合理
- 选择是否正确
- 工具是否可靠
- 检索结果是否有效

这才是一个 agent 真正落地的关键。

Day 5 让我进一步理解到：

RAG 不是一个附属功能，而是 agent 的重要能力基础；
工具、上下文和检索，是让 agent 从“会聊天”走向“会工作”的关键。

更成熟的 agent，不是只会输出一段漂亮的回答，而是：

- 能理解需求
- 能判断是否需要检索
- 能用工具获取真实数据
- 能在有限上下文中做出合理决策
- 能把结果整理成任务完成的输出

如果说 Day 1–4 主要是在理解“agent 是什么”，那么 Day 5 更接近“agent 怎么真正工作”。

这也是后续学习中最关键的一步：

从概念走向实现，从会说走向会做。
