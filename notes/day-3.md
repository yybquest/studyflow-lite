# Day 3: Context Engineering & Memory

## 1. 学习目标

今天的重点是理解：

- 什么是 Context Engineering
- Session 与 Memory 的区别
- 短期上下文和长期记忆在 agent 中如何工作
- 为什么好的上下文管理决定了 agent 的表现

## 2. 什么是 Context Engineering

Context Engineering（上下文工程）指的是：

- 如何组织和传递给模型的信息
- 如何让模型在当前任务中获得足够的背景
- 如何在有限的 token 预算中保留最有用的信息

简单来说，就是“把正确的信息、给正确的人、在正确的时间提供给模型”。

一个 agent 的表现，不仅来自模型本身，也来自它拿到的上下文质量。

## 3. 为什么上下文管理很重要

如果 agent 没有足够好的上下文，它可能会：

- 忘记前面的任务要求
- 误解用户意图
- 重复已经做过的事情
- 漏掉关键约束条件
- 产生不一致的回答

因此，agent 的关键能力不仅是推理，还包括：

- 记住当前对话状态
- 保留重要历史信息
- 识别无关噪音
- 为后续步骤准备合适的上下文

## 4. Session 与 Memory 的区别

### Session

Session（会话）通常是指：

- 当前这次对话的状态
- 一段连续交互过程中保留下来的上下文
- 例如：当前聊天窗口中的消息历史

特点：

- 适合短期对话
- 通常在一次对话中有效
- 可以帮助模型理解“刚刚发生了什么”

### Memory

Memory（记忆）通常指：

- agent 在多轮交互中保留的长期信息
- 用户偏好、任务历史、重要事实、知识总结
- 可以跨对话或跨任务复用的信息

特点：

- 更偏向长期保留
- 适合用户身份、历史需求、习惯和经验积累
- 可以提高 agent 的连续性和个性化

## 5. 短期上下文与长期记忆

### 短期上下文

短期上下文通常包括：

- 当前用户的问题
- 最近几轮对话
- 当前任务设定
- 相关工具调用结果

它的作用是：

- 帮助模型理解当前状态
- 保持对话连贯性
- 引导下一步动作

### 长期记忆

长期记忆通常包括：

- 用户的偏好或习惯
- 过去完成过的任务
- 重要事实储存
- 经验总结或知识归档

它的作用是：

- 让 agent 更像“有记忆的助手”
- 避免每次都从 0 开始
- 提升长期任务处理能力

## 6. 一个简单的对比

| 类型 | 作用 | 生命周期 | 典型例子 |
| --- | --- | --- | --- |
| Session | 维持当前对话状态 | 短期 | 当前聊天记录、最近问题和工具结果 |
| Memory | 保留长期知识和经验 | 长期 | 用户偏好、历史任务、关键知识总结 |
| Context | 给模型提供“理解当前任务所需的信息” | 动态 | 任务说明、步骤、上下文片段、检索结果 |

## 7. 为什么 Context Engineering 不是简单“塞更多内容”

有些人会认为：

> 把所有历史都塞给模型，效果一定更好。

但实际上这并不总是正确的。原因是：

- token 成本会变高
- 模型可能被噪声干扰
- 重要信息可能淹没在无关内容中
- 旧信息可能变得不准确或过时

所以真正重要的是：

- 选取正确的信息
- 去掉无关信息
- 保留关键约束
- 让模型看到最有用的上下文

这就是 context engineering 的核心价值。

## 8. Agent 中的上下文是如何流动的

一个典型流程可能是：

输入 → 任务理解 → 结合 session 情况 → 检索 memory / 历史记录 → 调用工具 → 生成答案 → 更新 memory

也就是说，agent 不只是一次性回答，而是：

- 读取当前状态
- 判断是否需要历史信息
- 选择什么上下文最有用
- 在执行后更新自己的记忆

## 9. 一个更现实的例子

假设用户说：

> 上次我们讨论过的方案要改成更偏简洁风格，这次我又要做一个产品介绍。

此时，agent 需要：

- 看当前 session 中的最近对话
- 识别“上次方案”的内容
- 保留“简洁风格”的要求
- 结合当前新需求
- 生成更符合用户偏好的结果

如果没有 session 和 memory 的管理，模型就可能忽略用户前面的约束，导致回答不一致。

## 10. Memory 在 agent 里的价值

Memory 让 agent 更像一个“有连续性的助手”，而不仅仅是一次性问答系统。

它可以帮助 agent：

- 记住用户的工作风格
- 记住常用约束条件
- 记住过去的任务目标
- 更好地维护长期合作关系

对真实应用来说，这一点非常重要。尤其是：

- 助手型 agent
- 客服型 agent
- 学习型 agent
- 工作流型 agent

都需要某种长期记忆能力。

## 11. 我的学习总结

Day 3 让我理解到：

一个好的 agent，不只是能推理和调用工具，它还需要管理上下文。

也就是说：

- Session 让它知道“现在在聊什么”
- Memory 让它知道“过去发生了什么”
- Context Engineering 让它知道“哪些信息最值得参考”

如果没有正确的上下文，agent 就可能表现得很聪明，但却无法稳定完成任务。

真正优质的 agent，不只是会回答，而是会管理信息、维护状态、记住重要事实，并在多轮交互中保持一致性。
