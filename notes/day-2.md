# Day 2: Agent Tools & MCP

## 1. 学习目标

今天的重点是理解 agent 是如何通过工具扩展能力的，以及 MCP（Model Context Protocol）在不同系统之间如何提供标准化交互。

## 2. 什么是 Agent Tool

Agent tool（工具）是让 agent 具备超越文本生成能力的关键组件。它可以让模型：

- 调用本地函数
- 访问外部 API
- 查询数据库
- 读取文件
- 执行脚本
- 执行计算或筛选任务

简单来说，工具让 agent 从“只会说”变成“会做”。

## 3. 为什么工具很重要

一个没有工具的模型通常只能：

- 生成文本
- 问答
- 进行简单推理

但它无法：

- 查询实时数据
- 调用外部系统
- 处理真实业务流程
- 读取本地文档和资源

工具提供了 agent 与真实世界连接的能力。 

## 4. Agent 的工具调用循环

输入 → 推理 → 判断是否需要工具 → 调用工具 → 收集结果 → 继续推理 → 输出

### 例子

如果用户问：

> 这份文档里有哪些关键点？

agent 可能会：

- 读取文档
- 提取关键段落
- 进行总结
- 返回最终答案

这里就需要工具，而不是只用模型直接生成答案。

## 5. Python function 与 structured tool 的区别

### Python function

适合简单任务：

- 计算
- 过滤列表
- 读取文件
- 查询简单数据

优点：

- 简单
- 容易实现
- 适合小型任务

缺点：

- 可扩展性有限
- 不适合复杂系统集成
- 形式不统一

### Structured tool

适合更标准化的 agent 接口：

- 明确输入参数
- 明确输出结构
- 可被其他系统复用
- 更适合多 agent / 多系统协作

优点：

- 更规范
- 更容易维护
- 更适合生产环境

缺点：

- 设计复杂一些
- 需要更明确的接口定义

## 6. 什么是 MCP

MCP（Model Context Protocol）是一种让不同系统更容易彼此协作的标准协议。它的核心思想是：

- 让 agent 能更统一地连接到工具、资源和外部系统
- 减少接口碎片化
- 让不同平台和工具能够以标准方式交互

MCP 可以帮助 agent 更好地连接：

- 数据源
- 工具
- 外部应用
- 不同服务系统

## 7. MCP 的意义

MCP 让 agent 的工具生态更像一个“标准化连接层”，而不是每个系统都要自己重新设计接入方式。

它让 agent 可以更容易地：

- 发现可用工具
- 调用标准接口
- 传递上下文
- 达到更好的跨系统协作

## 8. 设计一个好的 Agent Tool 的规则

### 规则 1：命名清晰

工具名称要清晰、明确，能够表达其用途。

例如：

- `search_documents`
- `read_file`
- `calculate_total`

而不是模糊名称，比如：

- `do_work`
- `handle_data`

### 规则 2：输入输出要明确

工具的参数和返回值应该清晰地说明：

- 输入是什么
- 输出是什么
- 发生错误时返回什么

这样 agent 更容易调用并理解结果。

### 规则 3：保持功能单一

一个工具尽量只做一件事，避免把太多逻辑塞进单个工具。

例如：

- 一个工具负责读取文件
- 一个工具负责搜索关键词
- 一个工具负责总结内容

而不要让一个工具同时做这些事情。这样更容易调试和维护。

## 9. MCP 的实际应用场景

一个常见场景是：

- 一个 agent 需要同时访问多个系统，如本地文件系统、数据库、外部 API
- 这些系统的接口格式不同
- 通过 MCP 可以统一桥接和调用

例如：

- 文档查询系统
- 数据库查询系统
- 企业内部知识库
- 任务管理工具

这些都可以通过标准协议对接给 agent。

## 10. 我的学习总结

Day 2 让我理解到：

Agent 的强大能力，不只是来自大模型本身，而是来自“工具能力”和“标准化连接能力”。

如果没有工具，就只是一个聊天模型；
如果有好的工具和标准接口，agent 才能完成真实任务。

MCP 的意义在于：

它让跨系统工具接入更加规范，也让不同 agent 生态之间更容易互通。
