# 阶段 1（RAG 闭环）改进清单 — 暂未实施

> RAG 最小闭环：chunker + embeddings + index + search_knowledge + summarizer。改进方向分五块，按性价比排序。

## 第一梯队：最该先做

1. **检索评估**：建小评测集（5~10 题 + 每个问题的正确文档/段落），测 recall@k。不度量就没法改进。
2. **混合检索**：关键词 + 语义融合（RRF）。补一个 BM25 关键词检索（rank_bm25）后与 dense 融合，提升专有名词/缩写/精确术语的召回。
3. **页眉/页脚去重**：用「短 + 高频」的频率统计，在切块前删掉重复的页眉页脚（如「CIKM '26, Rome, Italy」）。

## 第二梯队：规模化时做

4. **ChromaDB 升级**：语料到几千篇、numpy (现在是余弦相似度) 变慢时换向量库（持久化、ANN、增量、元数据过滤）。
5. **增量索引**：只嵌入新增文档、往索引追加，避免每次全量重建。
6. **元数据过滤**：search_knowledge 支持「只搜 paper / 只搜 notes」，检索更精准。

## 第三梯队：质量精修

7. **父文档检索**：检索用「小块」精准定位，返回给 LLM 的是「大块父节」（上下文更完整）。
8. **重排序**：先粗检索 top-20，再用 reranker（bge-reranker）精排到 top-5。
9. **更强嵌入模型**：bge-small → bge-m3（多语、8192 上下文、质量更好），代价是更大更慢。
10. **查询改写**：检索前改写/翻译 query，提升跨语言召回。

## 第四梯队：进阶 / 研究性

11. **语义分块**：按「嵌入相似度突变」切分，对无清晰标题的文档更好。
12. **HyDE**：先让 LLM 生成「假设答案」，再拿它去检索。
13. **多向量 / ColBERT**：late interaction，质量高但重。
14. **总结引用溯源**：summary 每句标注「出自原文第 N 行」。
