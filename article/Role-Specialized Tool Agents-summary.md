# 阅读笔记：Locate, Judge, Read

## 一句话总结
该工作提出 KnowForge 系统，将开放域多模态文档问答按“任务（job）”而非“轮次”拆分为定位（Locator）、桥接判断（Bridge Judge）、深度阅读（Deep Reader）等角色专用的工具智能体，在知识点索引与混合检索之上实现“搜索—判断—阅读”的物理工具隔离，在 M3DocVQA、MultiHop-RAG、MMLongBench-Doc 上以 35B MoE（3B 激活）模型显著超越同索引同模型的单轮检索问答和已发表强基线。

## 研究问题
- 现有单智能体 RAG 系统中，搜索与阅读共享同一循环，导致模型偏好搜索、阅读不足（74% 的问题从未使用阅读工具；曾出现 76 次调用中 66 次退回搜索）。
- 现有开放域系统（如 M3DocRAG、HiKEY）多为单轮检索或无智能体分工；现有多阶段 RAG 的流程切换依赖模型生成 token，子过程并非真正的阅读智能体。
- 多跳问题中第二跳文档缺失、跨页证据合并困难、错误拒答率偏高等问题。
- 核心追问：性能增益究竟来自“检索”还是“阅读”？角色分工、工具隔离、强制第二跳各自贡献多少？

## 方法
**整体框架：KnowForge，六个按职能分离的任务模块**（知识构建 → 仅搜索的 Locator → 桥接判断 → 受限证据池 → 仅阅读的 Deep Reader → 合成器）。

1. **知识构建与混合检索（3.1）**
   - 输入文件转为 Markdown，按文本/图像/表格/样例分片；图像和表格由视觉语言模型生成描述以参与文本检索。
   - 由 LLM 抽取原子知识点并构建带类型的关系图（M3DocVQA 上生成 332K 节点、299K 边）。
   - 检索采用 BM25 与稠密检索融合，取 top-8 锚点沿关系扩展一跳，附带相邻片段及图表上下文；单轮检索不调用 LLM。
   - 代码调度执行固定的“桥接实体”检查，追加 1–2 次后续查询（M3DocVQA 上触发约 48% 的问题）。

2. **Locator（3.2）**：仅配备查找类工具（search、list_books、book_toc 等），最多 L 轮，直到声明定位到证据，完全不接触阅读工具。

3. **Bridge judge（3.3）**：定位器停止后，通过固定提示让模型判断已找到片段是否覆盖全部所需知识要点，决定继续检索还是进入阅读。

4. **Multi-list ranked merge（3.4）**：将多次检索结果合并为统一证据池；池容量上限 30K tokens，按模态分池（图像 3K、表格 3K、示例 2K、文本为剩余）分别排序。

5. **Deep Reader（3.5）**：仅具备只读工具（片段上下文、单图/表读取、媒体上下文、查找图表等），最多 R 轮深度阅读证据池；刻意移除搜索工具。工具调用结果追加回同一证据池。

6. **Answer（3.6）**：合成器基于候选池和阅读器笔记撰写答案，格式检查器改写为基准要求格式（最短精确片段、不可回答/信息不足、Yes/No）。不同基准仅在最后格式化层和 agent 提示中一段规则上有差异，工具完全相同。

**消融系统设计**：单次检索（S4）、无深度阅读器（P1）、单智能体全工具（P0）、双角色完整流程（M5）。

## 贡献
- 提出按“任务（job）”而非“轮次”设计的多智能体文档问答框架，六个任务各配独立工具与停止规则，Locator 与 Deep Reader 工具物理隔离，第二跳由代码级 bridge judge 强制完成。
- 在三个公开基准上显著超越已发表系统（M3DocVQA F1 47.5 vs. 36.5；MMLongBench-Doc 上同一 35B-A3B 模型经流水线提升 12.2 分，达到 GPT-4o 读图水平）。
- 通过逐任务消融量化角色分离、Deep Reader 和混合检索各自的增益：固定索引时 35B 比 7B 读者仅提升 2.4 F1，而固定模型时流水线比单次推理提升 7.1 F1；全部支撑文档被找到比例从 73.3% 提升到 84.6%。
- 提出类型化、有容量限制的证据池，并证明类型化是保证大池安全性的关键。
- 公开三个基准索引及配套脚本、提示和参考运行器供第三方复现。

## 关键技术
- **角色专用工具隔离**：Locator 仅配 search/list_books/book_toc 等查找类工具；Deep Reader 仅配片段上下文、单图/表读取、媒体上下文、查找图表等只读工具，二者工具集互不重叠，从机制上防止“退化回搜索”。
- **代码级强制第二跳**：检索停止后由代码调度（非模型 token 触发）执行固定“桥接实体”检查，追加 1–2 次去重后续查询；该机制在 M3DocVQA 上触发约 48% 的问题，是 MultiHop-RAG 全部证据发现率提升 14.5 个百分点的最大贡献因素。
- **桥接判断器 JSON 协议**：识别出桥接实体但其文档尚未检索时输出 `need_more=true` 并给出最多两条去重检索查询，否则输出 `need_more=false`，结果以固定 JSON 返回。
- **类型化多列表排序合并**：池容量上限 30K tokens；按模态分池（图像 3K、表格 3K、示例 2K、文本为剩余）分别排序，保护高排名图/表/示例片段不被同搜索排名的文本驱逐（达容量上限问题 F1 30.6 vs 23.3）。
- **混合检索**：BM25 与稠密检索融合，取 top-8 锚点沿关系图扩展一跳；纯稠密检索会显著降低 F1（−2.5）并拖累首轮召回。
- **共享循环协议**：模型每轮输出 JSON 格式的思考与工具调用，禁止在循环中直接写入答案（答案由合成器基于收集材料生成），材料足够即停止。
- **单行停止规则提醒**：在每个工具结果后附上单行停止规则提醒，比在系统提示开头放置规则更有效。
- **轮次预算 4+4**：Locator+Reader 配额在 4+4 时 F1 跃升至 50.9（1+1 至 3+3 约 46.2–46.7），是覆盖最多三跳最坏情况的最小有效预算；两角色轮次预算存在非加性互补效应（同时减少损失 4.7 > 各自损失之和 2.9）。
- **护栏与格式检查器**：要求以严格 `FINAL ANSWER` 行结尾；格式检查器只做规范化或缩短，不能添加原文信息。

## 术语表

- **开放域多模态文档问答**：在无需预先限定文档范围的情况下，对包含文本、图像、表格等多种模态的文档进行问答的任务。
- **知识点索引**：由LLM从文档中抽取原子知识点并构建的带类型关系图，用于结构化定位与检索。
- **工具智能体**：配备特定工具集、承担特定职责的智能体，通过调用工具完成子任务。
- **角色分工**：将问答流程按职能拆分为多个专门角色（如定位、判断、阅读），各角色工具互不重叠。
- **KnowForge**：本文提出的按任务角色拆分模块的开放域多模态文档问答系统。
- **Locator**：仅配备查找类工具的专用智能体，负责定位含答案的文档与片段。
- **Bridge judge**：桥接判断模块，判断已收集证据是否覆盖全部所需知识点，决定是否继续检索。
- **Deep Reader**：仅具备只读工具的角色专用智能体，对证据池进行深度阅读以提取答案。
- **合成器**：基于候选池和阅读器笔记撰写最终答案的模块。
- **证据池**：汇集定位器与桥接判断器多次检索结果的统一证据集合，供阅读器使用。
- **混合检索**：融合BM25稀疏检索与稠密检索的检索方式。
- **BM25**：一种基于词频的经典稀疏检索算法。
- **稠密检索**：基于向量嵌入相似度的检索方法。
- **桥接实体**：多跳问题中连接第一跳与第二跳文档的关键实体。
- **强制二次跳转**：由代码在检索停止后强制执行的固定桥接实体检查与补充查询机制。
- **类型化证据池**：按模态（图像、表格、示例、文本）分池并分别排序的证据池。
- **多列表排序合并**：将多次检索结果合并为统一证据池的策略。
- **单智能体RAG**：由单一模型同时承担检索与阅读的检索增强生成系统。
- **多阶段RAG**：将检索问答拆分为多个阶段流程的检索增强生成方法。
- **图结构RAG**：利用知识图谱结构进行检索的检索增强生成方法。
- **M3DocVQA**：一个多模态多文档视觉问答基准数据集。
- **MultiHop-RAG**：一个需要多跳推理的检索增强生成基准数据集。
- **MMLongBench-Doc**：一个面向长文档的多模态问答基准数据集。
- **视觉语言模型**：能同时处理图像与文本的模型，用于生成图像和表格描述。
- **MoE**：混合专家模型架构，通过稀疏激活提升参数效率。
- **激活参数**：MoE模型单次推理中实际参与计算的参数量。
- **F1**：精确率与召回率的调和平均，用于评估答案质量。
- **Doc@all**：全部支撑文档被检索到的比例指标。
- **全证据发现率**：所有必要证据均被检索到的比例。
- **token-F1**：以token为单位的F1评分，用于评估答案与参考答案的重叠度。
- **错误拒答**：对实际可回答的问题输出“不可回答”或“信息不足”的错误。
- **消融实验**：通过移除或替换系统组件来量化各组件贡献的实验方法。
- **轮次预算**：分配给定位器与阅读器的最大交互轮数限制。
- **停止规则**：智能体在何种条件下停止工具调用的规则。
- **护栏提示**：附加在每个问题上的约束性提示，规范模型输出格式与行为。
- **格式检查器**：对合成器输出进行规范化或缩短以符合基准要求的后处理模块。
- **one-shot基线**：仅进行一次检索问答的基线配置。
- **记忆污染**：模型在预训练中已见过测试数据，导致评测虚高的风险。
- **CC BY-NC 4.0**：一种允许非商业使用并需署名的知识共享许可协议。
- **ODC-BY**：一种允许使用并需署名的开放数据共享许可协议。
- **跨页证据合并**：将分布在多个页面上的证据整合以回答同一问题的过程。
